# SCPP: A Unified Python Library for Soft Clustering 

Kiyan Rezaee #∗ and Morteza Ziabakhsh and Artin Bahrampour and Seyed Mo-hammad Ghoreishi and Asal Khaje and Ali Sajedifar and Manny Chalak and Ava Zerafatangiz and Sadegh Eskandari 

Abstract 

In this paper, we present SCPP (Soft Clustering Python Package), an open-source Python framework for soft clustering. SCPP establishes a canonical, scikit-learn-compatible es-timator interface that standardizes model training, prediction, membership representa-tion, evaluation, and benchmarking across heterogeneous soft clustering methods, includ-ing fuzzy, probabilistic, graph-based, matrix factorization, and deep learning methods. The framework currently integrates 40 representative algorithms together with a compre-hensive benchmarking comprising datasets, clustering quality metrics, and standardized runtime, memory, and scalability evaluation. SCPP further provides extensive documen-tation, practical examples, automated testing, and seamless integration with the scien-tific Python ecosystem, enabling reproducible experimentation and straightforward exten-sion with new algorithms. The source code is publicly available at https://github.com/ soft-clustering/soft-clustering .

Keywords: soft clustering, Python package, open-source software 

1 Introduction 

Soft clustering models overlapping cluster structure by assigning each observation a vector of fractional memberships rather than a single cluster label. It has become an established paradigm with applications in bioinformatics, natural language processing, computer vision, recommender systems, community detection, and scientometrics Dogan and Avvad (2025); Liu et al. (2025); Pattanayak et al. (2024); Cangemi et al. (2025); Chi et al. (2025); Oskouei et al. (2025); Rezaee et al. (2025). Recent studies further demonstrate its effectiveness in emerging domains such as software modularization, where it outperforms hard clustering by identifying components with cross-cutting responsibilities Ziabakhsh et al. (2025). Despite extensive methodological advances, the software ecosystem for soft clustering remains fragmented. Existing implementations are distributed across independent Python libraries that differ in algorithm coverage, APIs, parameter conventions, membership rep-resentations, and benchmarking support Pedregosa et al. (2011); McInnes et al. (2017); Novikov (2019); Kasa et al. (2024); Leiber et al. (2023); Warner et al. (2024); Dias (2019); oli (2026). Most libraries focus on a single family of methods rather than providing a com-mon abstraction across heterogeneous paradigms. Consequently, researchers must combine incompatible software packages, hindering reproducibility, systematic benchmarking, and fair empirical comparison. Table 1 summarizes the current ecosystem. Existing libraries either specialize in individual algorithm families or provide limited benchmarking support. None combines broad algorithmic coverage, a unified estimator interface, and an integrated benchmarking framework within a single software architecture.

To address these limitations, we present SCPP (Soft Clustering Python Package), an open-source Python framework that establishes a canonical software abstraction for soft clustering. SCPP unifies heterogeneous algorithms under a scikit-learn-compatible estimator interface, standardizing model training, membership representation, evaluation, and benchmarking. This enables reproducible experimentation and direct comparison of previously incompatible methods with minimal code changes. The contributions of this work are fourfold: 1. A unified software abstraction for soft clustering. SCPP introduces a scikit-learn-compatible estimator interface that enables diverse soft clustering algorithms to be trained, evaluated, and compared through the same workflow, independent of their underlying methodology. 2. Comprehensive algorithmic coverage within a common framework. The library unifies 40 representative soft clustering algorithms spanning the principal methodological families under a consistent API. 3. An integrated benchmarking and reproducibility ecosystem. SCPP provides standardized datasets, clustering quality metrics, runtime, memory, and scalability benchmarking modules that facilitate fair and reproducible empirical evaluation. 4. Research-grade software engineering infrastructure. To support reliable sci-entific software, the package is distributed through PyPI under the MIT license and is accompanied by comprehensive documentation, extensive examples, automated test-ing comprising 241 unit tests across 41 modules, and continuous integration workflows. The architecture is designed to facilitate long-term extensibility and integration with the broader scientific Python ecosystem. 2Figure 1: Overall software architecture of SCPP. 2 Design and Implementation 

SCPP is designed as a reusable software platform . Its central design principle is that het-erogeneous soft clustering methods should expose a common software abstraction despite substantial differences in their mathematical formulations and optimization procedures. This abstraction standardizes the complete lifecycle of a soft clustering estimator, includ-ing model configuration, training, prediction, membership representation, evaluation, and benchmarking, allowing algorithms to be used interchangeably within a common experi-mental workflow. Figure 1 illustrates the logical architecture of SCPP, which is organized into five soft-ware layers. End users interact exclusively through a canonical, scikit-learn-compatible estimator interface, while the underlying implementation encapsulates multiple families of soft clustering algorithms within a common API. A dedicated benchmarking layer provides standardized evaluation infrastructure, and the framework is complemented by documen-tation, automated testing, and seamless integration with the scientific Python ecosystem. 3This layered architecture clearly separates reusable research infrastructure from algorithm-specific implementations, improving maintainability, extensibility, and reproducibility. The project repository follows the same modular design. The soft clustering/ pack-age contains the unified estimator interface and algorithm implementations, and benchmarking/ 

provides reusable experiment runners, evaluation metrics, runtime analysis, memory pro-filing, scalability evaluation, and dataset management. User tutorials, API references, and developer documentation are maintained in docs/ , practical examples are distributed through examples/ , and software correctness is validated in tests/ . Project configura-tion and distribution are managed through pyproject.toml , pytest.ini , README.rst ,and .readthedocs.yaml , providing a maintainable repository structure for both users and contributors. Every estimator implements the standard methods fit , predict , predict proba , and 

fit predict , while exposing consistent outputs through attributes such as membership ,

labels , and, when available, cluster centers and weights . Consequently, visualiza-tion, evaluation, benchmarking, and downstream applications operate independently of the underlying clustering algorithm without requiring algorithm-specific integration code. The example below illustrates a typical workflow that applies uniformly to every estimator in the framework.

Appendix C. Soft Clustering Evaluation Framework 

SCPP provides a unified evaluation framework for both hard and soft clustering methods. In addition to conventional clustering metrics commonly used in the literature, the framework includes several soft-clustering-specific measures that directly operate on the membership matrix U . For hard cluster assignments, SCPP integrates widely used internal and external evaluation metrics from scikit-learn . Internal metrics assess cluster structure without requiring ground-truth labels, while external metrics measure agreement with reference labels when available. Unlike conventional clustering libraries that focus primarily on hard-label evaluation, SCPP additionally provides dedicated metrics for soft clustering analysis. These metrics quantify partition fuzziness, membership uncertainty, cluster compactness, and prototype separation directly from the membership matrix. To simplify benchmarking, SCPP exposes a unified evaluation interface that automati-cally computes all applicable metrics from cluster labels, membership matrices, and cluster prototypes. Appendix D. Computational Performance Benchmarking 

In addition to clustering quality evaluation, SCPP provides an integrated benchmarking framework for measuring computational performance. The framework evaluates runtime, scalability, and memory consumption using a unified interface applicable to all clustering algorithms implemented in the library. These benchmarks provide a standardized protocol for comparing the practical efficiency of different soft clustering methods beyond clustering accuracy alone. The runtime benchmark repeatedly executes the training procedure and, when available, the prediction stage of a clustering model. Average execution time and standard deviation are reported across multiple runs to reduce sensitivity to transient system fluctuations and provide a more stable estimate of computational cost. To assess scalability, SCPP evaluates clustering algorithms on progressively larger sub-sets of the same dataset. By default, experiments are performed using sample sizes ranging from 100 to 10 000 observations. For each subset, both runtime and memory consump-tion are recorded, allowing users to analyze how computational requirements evolve as the dataset size increases. The memory profiling benchmark measures the resident memory usage of the clustering process before and after model fitting. In addition to reporting total memory consumption, the framework computes the memory overhead introduced by training and records the peak observed memory footprint. Optional garbage-collection warmup is performed before benchmarking to reduce variability caused by previously allocated objects. All computational benchmarks are implemented using a common evaluation interface and can be applied directly to SCPP soft clustering clustering models. 11 Appendix E. Comprehensive Testing Units 

To ensure the reliability of SCPP, we developed a comprehensive automated testing in-frastructure consisting of 241 unit and integration tests distributed across 41 dedi-cated test modules . Collectively, these tests validate every one of the 40 clustering algorithms included in SCPP, making software verification a first-class component of the package development process. 

E.1 Test Suite Organization 

The testing framework follows a modular design in which each clustering algorithm is asso-ciated with a dedicated test file. This structure promotes maintainability, simplifies debug-ging, and enables independent verification of algorithm-specific functionality. The tests/ directory contains: 

• conftest.py : Shared fixtures, reproducible random data generators, and testing utili-ties. 

• test package init.py : Validation of package imports and public API exposure. 

• test [name of the method].py : Forty algorithm-specific testing modules covering all methods implemented in SCPP. 

E.2 Verification Strategy 

Rather than merely confirming successful execution, the testing framework systematically validates a broad collection of theoretical and implementation-level properties. 

Output Validation. All algorithms are evaluated to ensure that generated outputs pos-sess the correct dimensions and structural properties, including membership matrices, clus-ter assignments, centroids, topic distributions, community memberships, and latent repre-sentations. 

Mathematical Consistency. Whenever applicable, the testing framework evaluates sev-eral core mathematical invariants underlying each clustering algorithm. These include the non-negativity of memberships and probability estimates, satisfaction of normalization con-straints, validity of parameter ranges, consistency with the corresponding probabilistic or possibilistic formulation, and numerical stability during iterative optimization. Together, these tests provide strong evidence that the implementations faithfully adhere to their the-oretical foundations while remaining robust under practical operating conditions. 

Model State Verification. After model fitting, the testing suite ensures that all ex-pected internal attributes are correctly instantiated and exposed through the public inter-face. This verification step is essential for confirming that optimization results are faithfully persisted within each estimator and remain consistent across subsequent operations. The checks include fundamental learned quantities such as centers , memberships , and 

objective trajectory , as well as algorithm-dependent state variables, including conver-gence diagnostics, posterior parameter estimates, and higher-level latent representations 12 such as topic structures and community memberships. Together, these validations guaran-tee the integrity and accessibility of the learned model state across all implementations in SCPP. 

Parameter Robustness. Every algorithm is evaluated under multiple configurations, including different cluster counts, initialization strategies, fuzzification coefficients, conver-gence tolerances, and optimization settings. 

Edge Cases and Failure Modes. We also include invalid hyperparameter configura-tions, degenerate or ill-posed datasets, single-sample inputs, sparse matrix representations, disconnected or isolated graph structures, unsupported initialization schemes, and numeri-cally unstable configurations. In each case, the framework verifies that the implementation raises the appropriate exceptions with consistent semantics and informative error messages, thereby ensuring predictable and reliable failure behavior throughout the library. 

Reproducibility. For all stochastic algorithms, repeated executions using identical ran-dom seeds are required to produce identical outputs. These tests guarantee deterministic behavior and facilitate reproducible scientific experimentation.

G.4 Output of Soft Clustering and Conversion to Numerical Quantities 

The membership matrix U is the most informative output of a soft clustering algorithm, as it provides a probabilistic or fuzzy assignment of each sample to all clusters rather than a single discrete label. This representation enables a variety of downstream analyses and interpretations. For compatibility with traditional pipelines that require crisp labels, hard assignments can be obtained by selecting the cluster with the highest membership value using np.argmax(U, axis=1) . The maximum membership value itself, computed with np.max(U, axis=1) , can be interpreted as a per-sample confidence score indicating how strongly a point belongs to its most likely cluster. The distribution of memberships across clusters also allows quantifying uncertainty through entropy measures, where higher entropy values indicate ambiguous samples that belong similarly to multiple clusters. Fi-nally, aggregating memberships across samples provides insight into cluster structure; for example, np.sum(U, axis=0) yields the effective mass or typicality of each cluster, offering a soft estimate of cluster size that reflects partial memberships rather than strict counts. Together, these analyses make the membership matrix a powerful tool for understanding cluster structure, confidence, and ambiguity in the data. G.6 Summary of the Integrated Pipeline 

By enforcing standardized interfaces and exposing the full soft membership matrix, SCPP eliminates fragmentation across individual implementations. It allows researchers to focus 22 on novel algorithmic contributions and domain insights while seamlessly leveraging the mature, battle-tested tools of the PyData ecosystem. All code examples are production-ready, tested with Python 3.10, and support scalable extensions via dask, polars, and faiss. This integration makes SCPP suitable for both academic benchmarking and real-world deployment across tabular, text, image, and graph data. The recommended end-to-end workflow for using SCPP is: 1. Load and preprocess raw data into a feature matrix X or affinity matrix A using the modality-specific strategies and packages in Tables 1–2. 2. Fit the model with the unified SCPP interface. 3. Extract and interpret the membership matrix U to obtain hard labels, confidence scores, entropy (uncertainty), and cluster masses. 4. Evaluate comprehensively using both soft-specific internal metrics (PC, PE, XB) and standard external metrics (ARI, NMI) via scikit-learn and custom NumPy functions.
